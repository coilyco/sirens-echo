Every feature a deployment may turn on or off.
Generated by `just flags`, every name prefixed SIRENS_ECHO_. The second column
is the default, and an unparsable value is fatal at startup rather than ignored.
Why the switches live where they do: docs/sirens-echo-tuning.md

NAME                               ON?   WHAT IT TURNS ON
COALESCE_ENABLED                   off   Batch a member's rapid comments into one turn on a worker pool.
DISCORD_COMMANDS                   off   Register and serve Discord application commands.
DISCORD_DM_ENABLED                 off   Admit direct messages, which carry no guild moderation.
DISCORD_ENABLED                    on    Open the Discord gateway session at all.
DISCORD_GATEWAY                    on    Connect this process's own gateway session. Off, it posts over REST and hears Discord only through the event queue.
DISCORD_QUEUE                      off   Take Discord events from the Postgres queue the intake writes, and send this process's own gateway events there too.
JEV_DIRECT_TOOLS                   off   Answer from a tool's own reply template, with no model call, when route.jev picks that server and tool at 0.9 or above.
MCP_REEXPORT                       off   Offer the roster's own tools over /mcp beside turn. They bypass the turn pipeline's checks, so they require the deployment token.
SLACK_ENABLED                      off   Open the Slack Socket Mode session. Needs both Slack tokens and a Slack access policy, and refuses to start without them.
THREAD_SUMMARY                     off   End a thread turn by editing this service's first reply there rather than posting another, so the thread carries one living answer.
